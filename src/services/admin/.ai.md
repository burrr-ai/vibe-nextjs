# Admin Service

Admin-only service. Has its own login/dashboard separate from regular users (app).

## Routes

| Path | Purpose |
|------|---------|
| `/admin` | Dashboard (login required) |
| `/admin/login` | Admin login |
| `/admin/sign-up` | Admin sign-up |

**Always tell the user** how to enter the admin:
> "In the browser, go to `/admin`. e.g., `localhost:3000/admin` or `your-deployed-domain/admin`"
>
> If it's your first time, you need to create an account at `/admin/sign-up` first.

## Sign-up Exposure Rules (Important)

### 1. The login screen **must** expose a sign-up link
- Admins are users who cannot see folders/files, so they cannot find the `/admin/sign-up` path on their own.
- Therefore the `/admin/login` screen must **always** have a link/button like "No admin account? Sign up".
- Do not remove this link when modifying or rebuilding the login form.

### 2. Keep the screen alive **while** sign-up is configured
- Default state: `/admin/sign-up` is **active**. The sign-up link is exposed on the login screen too.
- When the user says **"disable admin sign-up"**:
  - Disable the `/admin/sign-up` page (e.g., 404 / notice / API block)
  - **Also remove** the sign-up link on the `/admin/login` screen
  - These two move as a set — disabling only one side confuses the user.

### 3. Keep the warning text on the sign-up screen
- `/admin/sign-up` already has a notice box that says "After you create your account, be sure to disable admin sign-up".
- Even when the sign-up form is actually implemented, **keep this warning** as is.

## Layer Rules

- `services/admin/api/`, `state/`, `page/` follow the rules in `services/.ai.md`, `api.ai.md`, `state.ai.md`, `page.ai.md` exactly.
- Admin-only state (`useAdminUser`, etc.) is not mixed with the `app` service. No cross-imports.
- Auth guards run in the server layout at `services/admin/page/layout/` (no middleware).

## Checklist When Building Admin Screens

- [ ] Is the route under `/admin/*`?
- [ ] Does the page require login? → Check the session guard in the layout
- [ ] Is the sign-up link on the login screen still alive (unless it's been disabled)?
- [ ] Did you add the new menu to `navItems` in `page/layout/client.tsx`?
