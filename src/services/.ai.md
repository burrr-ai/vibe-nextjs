# Services

## 구조
```
services/
  {service}/          ← app, admin 등
    api/{domain}/     ← 서버 액션 (repository 경유)
    state/{domain}/   ← 상태 관리 (comwit)
    page/{route}/     ← 페이지 컴포넌트
      layout/         ← 서비스별 레이아웃 (서버+클라이언트)
```

## 규칙
- 서비스 간 크로스 import 금지 (admin → app 금지)
- 공용은 `src/lib/` 또는 `src/server/`
- 의존 흐름: `page → state → api → repository`
- 개발 순서: api → state → page (바텀업)
- Root Layout (`src/lib/layout/root-layout/`): 글로벌만 (StateProvider, OverlayProvider, Toaster)
- 서비스 Layout (`services/{service}/page/layout/`): 인증 + UI

## Import Rules
- **외부에서는 반드시 index.ts 통해서만 import**
  - ✅ `import { ProductAPI } from '@/services/app/api/product'`
  - ❌ `import { create } from '@/services/app/api/product/actions/create'`
  - ❌ `import type { Product } from '@/services/app/api/product/types'`
- 같은 domain 폴더 내에서는 relative import 허용
- ESLint `index-only-import` rule 강제
- api는 주로 state에서 호출한다. 서버 컴포넌트에서 직접 호출하여 `silent()` init에 쓰는 경우도 있으나, **클라이언트 컴포넌트에서 useEffect로 api를 직접 호출하는 것은 금지**
