# Services

## Structure
```
services/
  {service}/          ← app, admin, etc.
    api/{domain}/     ← Server Actions (routed through repository)
    state/{domain}/   ← State management (comwit)
    page/{route}/     ← Page components
      layout/         ← Per-service layout (server + client)
```

## Rules
- No cross-imports between services (admin → app is forbidden)
- Shared code lives in `src/lib/` or `src/server/`
- Dependency flow: `page → state → api → repository`
- Development order: api → state → page (bottom-up)
- Root Layout (`src/lib/layout/root-layout/`): global only (StateProvider, OverlayProvider, Toaster)
- Service Layout (`services/{service}/page/layout/`): auth + UI

## Import Rules
- **External imports MUST go through index.ts only**
  - ✅ `import { ProductAPI } from '@/services/app/api/product'`
  - ❌ `import { create } from '@/services/app/api/product/actions/create'`
  - ❌ `import type { Product } from '@/services/app/api/product/types'`
- Relative imports are allowed within the same domain folder
- Enforced by ESLint `index-only-import` rule
- api is mainly called from state. It may also be called directly from server components for `silent()` init, but **calling api directly from a client component via useEffect is forbidden**
